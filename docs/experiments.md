# 실험 기록장

얼굴 분석 백엔드·기준값을 바꿀 때마다 무엇을 왜 바꿨고 결과가 어땠는지 남긴다.
포트폴리오의 "정확도를 X에서 Y로 올렸다"는 근거가 이 문서다.

## 기록 방법

```powershell
cd pipeline
.venv\Scripts\skpipe bench ..\samples\faces --name "애니 기본 비교" --note "lbpcascade + DINOv2 처음 비교"
```

- 실행할 때마다 `experiments/{날짜시각}-{이름}/`에 `result.json`(전체 기록)과 `result.md`(요약)가 생기고, 아래 **실험 목록** 표에 한 줄이 자동으로 추가된다.
- 함께 남는 조건: 데이터셋 지문(파일 이름·크기 해시), 캐릭터·이미지 수, git 커밋(커밋 안 된 변경 여부), 라이브러리 버전, 백엔드별 기준값.
- **데이터셋 지문이 같아야 숫자를 비교할 수 있다.** 사진을 더하거나 빼면 지문이 바뀐다.
- 이미지 파일 자체와 PC 절대 경로는 기록하지 않는다 (저장소에 올라가므로).
- 자동으로 추가된 행 아래 **해석** 칸에는 사람이 결론을 적는다.

## 지표

| 지표 | 뜻 | 좋은 방향 |
| --- | --- | --- |
| 검출률 | 얼굴을 찾은 이미지 비율 | ↑ |
| AUC | 같은 인물 쌍과 다른 인물 쌍을 유사도로 가르는 능력 (0.5 무작위 ~ 1.0 완벽) | ↑ |
| 최적 기준 | 같은/다른 인물을 가장 잘 가르는 유사도 → `issue_below` 후보 | – |
| 균형 정확도 | 최적 기준에서 (같은 인물 맞힘률 + 다른 인물 맞힘률) / 2 | ↑ |
| 식별 정확도 | 한 장씩 빼고 캐릭터 평균과 비교해 맞는 캐릭터를 고르는 비율 | ↑ |
| ms/장 | CPU에서 이미지 한 장 처리 시간 | ↓ |

## 해석

### 실험 0 — 실사 사진 동작 확인 (2026-11-20)

- **목적:** 새 백엔드(`yunet-dino`, `anime-dino`)와 `bench` 도구가 끝까지 도는지 확인. 정확도 측정이 아님.
- **데이터:** 실사 인물 2명 × 4장 (원본·좌우반전+밝기·흐림·축소). 공개 샘플 이미지(scikit-image 우주비행사, OpenCV 샘플)로 만든 변형이라 실제 연재물과 다르다.
- **결과:** `opencv`·`yunet-dino` 모두 검출률 100%, AUC 1.0. `anime-dino`는 검출률 12% (애니 전용 검출기라 실사 얼굴은 거의 못 찾음 — 예상대로).
- **알게 된 것:** DINOv2는 다른 인물끼리도 유사도가 약 0.32로 SFace(약 0.09)보다 높다. **백엔드마다 기준값을 따로 둬야 한다**는 근거.
- **다음:** 애니체 캐릭터 사진(캐릭터당 5~10장, 2명 이상)으로 같은 비교를 한다.

### 실험 1 — 반실사 애니 a·b (2026-11-20)

- **목적:** 애니 백엔드(`anime-dino`)가 실사 모델보다 나은지, AI로 만든 캐릭터에서 처음 측정.
- **데이터:** 이미지 생성 도구로 만든 반실사(3D 애니풍) 캐릭터 2명 × 6장. **같은 설명에서 머리색만 다르게**(a 검정 단발 / b 갈색 단발, 둘 다 눈 밑 점·베이지 니트) 만든, 일부러 닮은 쌍.
- **결과**

  | 백엔드 | 검출률 | AUC | 같은 인물 평균 | 다른 인물 평균 | 식별 정확도 |
  | --- | --- | --- | --- | --- | --- |
  | opencv | 100% | 0.503 | 0.540 | 0.555 | 42% |
  | yunet-dino | 100% | 0.570 | 0.775 | 0.757 | 83% |
  | anime-dino | 33% | 0.778 | 0.798 | 0.727 | 100% |

- **해석**
  - `opencv`(SFace)는 **무작위 수준**. 같은 캐릭터끼리(0.54)보다 a↔b(0.56)가 더 비슷하게 나온다 → 실사 얼굴 인식 모델은 이 그림체에 쓸 수 없다.
  - `yunet-dino`는 얼굴은 다 찾지만 같은/다른 인물 차이가 **0.02**뿐이라 기준값으로는 거의 못 가른다. 여러 장 평균(식별 정확도 83%)에는 정보가 조금 있다.
  - `anime-dino`는 숫자가 가장 좋아 보이지만 **판정 불가.** 애니 캐스케이드가 반실사 얼굴을 12장 중 4장만 찾아 비교 쌍이 같은 인물 3·다른 인물 3쌍뿐이다. 자동 기록의 "가장 잘 가른 백엔드"는 검출률·쌍 수를 보지 않아 잘못 뽑았다 → bench 판정 기준을 고친다.
- **원인 (가설):** 두 임베딩 모두 **색에 둔감하게 학습**됐다. SFace는 정렬된 얼굴 안쪽만 보고 머리카락을 거의 잘라내며, DINOv2는 학습 때 색 증강(color jitter)을 써서 색이 바뀌어도 같은 물체로 본다. 그런데 이 서비스에서는 "머리색이 바뀌었다"가 바로 잡아야 할 일관성 오류다 — 일반 얼굴 인식과 목표가 반대다.
- **다음:**
  1. bench 판정에 최소 검출률·비교 쌍 수 조건 추가
  2. 얼굴 주변(머리카락 포함) 색 분포를 DINOv2와 합친 백엔드(`yunet-dino-color`)로 같은 데이터 재실험
  3. 캐릭터당 10장 이상 + 확실히 다르게 생긴 캐릭터 c 추가 (쉬운 구분 / 어려운 구분 분리)
  4. 장기: 의도한 외형 변화(염색·의상)는 캐릭터 "외형 버전"으로 등록해 회차별 기준으로 비교

### 실험 2 — 색 특징 추가 (2026-11-20)

- **목적:** 실험 1의 가설("임베딩이 색에 둔감해서 머리색만 다른 a·b를 못 가른다") 확인.
- **바꾼 것:** `yunet-dino-color` 추가 (YuNet + DINOv2 0.6 + Lab 색 히스토그램 0.4). bench 판정 기준 추가 (검출 80%·비교 쌍 각 10개 미만이면 "신뢰도 낮음", 결론에서 제외). 데이터는 실험 1과 같음 (지문 `3f6be87122cc`).
- **결과**

  | 백엔드 | 검출률 | AUC | 같은 인물 평균 | 다른 인물 평균 | 식별 정확도 | 신뢰도 |
  | --- | --- | --- | --- | --- | --- | --- |
  | opencv | 100% | 0.503 | 0.540 | 0.555 | 42% | ✓ |
  | yunet-dino | 100% | 0.570 | 0.775 | 0.757 | 83% | ✓ |
  | anime-dino | 33% | 0.778 | 0.798 | 0.727 | 100% | ⚠ 검출·쌍 부족 |
  | **yunet-dino-color** | 100% | **0.611** | 0.845 | 0.827 | 83% | ✓ |

  추가 분석 — 색 특징만 따로 (같은 데이터, YuNet 얼굴 박스 기준):

  | 색 특징 영역 | AUC | 같은 인물 평균 | 다른 인물 평균 |
  | --- | --- | --- | --- |
  | 머리 띠 (위 45%) | 0.645 | 0.925 | 0.901 |
  | 전체 영역 | **0.768** | 0.977 | 0.965 |
  | 둘 합침 | 0.681 | 0.951 | 0.933 |

- **해석**
  - **가설은 맞았다.** 색 특징만으로 0.768로, DINOv2(0.570)·SFace(0.503)보다 a·b를 잘 가른다. 색에 둔감한 임베딩이 문제였다.
  - 그런데 DINOv2와 6:4로 섞으니 0.611로 **오히려 색만 쓴 것보다 낮아졌다.** 이 쌍에서는 DINOv2가 구분 정보 없이 섞여 들어가 희석시킨다.
  - 색 유사도가 같은 인물·다른 인물 모두 0.9 이상으로 몰려 있다. 히스토그램이 **두 캐릭터에 공통인 색(피부·베이지 니트·따뜻한 배경)에 지배**되고, 정작 다른 머리카락 픽셀은 일부라서 차이가 작다.
  - 머리 띠(위 45%)가 전체보다 낮은 건, 그 영역에 이마·배경이 섞이고 같은 캐릭터 안에서도 앞머리·조명이 달라서로 보인다.
  - `anime-dino`는 판정 기준에 따라 결론에서 빠졌다 (실험 1의 잘못된 결론이 다시 나오지 않음).
- **주의:** 12장·2명이라 숫자가 흔들리기 쉽다. **이 데이터로 가중치를 맞추면 과적합**이므로 가중치 조정은 데이터를 늘린 뒤에 한다.
- **다음**
  1. 머리카락 픽셀만 골라 대표 색을 비교 (피부색·배경 제외, 주요 색 추출) — 공통 색에 묻히지 않게
  2. 데이터 확대: 캐릭터당 10장 이상 + 확실히 다른 캐릭터 c → 가중치·기준값은 그 데이터로
  3. 애니 검출기가 못 찾으면 YuNet으로 다시 찾기 — 반실사 애니에서 `anime-dino` 검출 33% 문제
  4. 장기: "누구인가(얼굴 형태)"와 "외형이 맞는가(색)"를 두 단계로 나눠 판정 (지금처럼 한 점수로 섞지 않기)

### 실험 3 — Veo로 만든 회차 영상 cafe-semi ep01 (2026-11-21)

- **목적:** 사진 묶음(bench)이 아니라 **실제 회차 영상 한 편**에서 컷 분할 → 얼굴 비교 → 이슈 판정 전체가 맞게 도는지, 백엔드별로 의도한 오류 컷을 잡는지 확인.
- **데이터:** [samples/cafe-semi](../samples/README.md). Google AI Studio에서 직접 생성 (레퍼런스는 Gemini 이미지, 영상은 Veo 이미지→영상).
  - 바이블: yuna(검정 단발·눈 밑 점·베이지 니트, 정면·3/4·측면 3장), minho(안경·데님 재킷, 정면·측면 2장)
  - 영상: 8초 클립 5개를 30fps로 합친 40초. 마지막 컷(0:32~0:40)만 **yuna 머리색을 갈색으로 바꾼 의도적 오류**
  - 라벨 `ep01.labels.csv`: ok 4 (yuna 3·minho 1) · ng 1
- **실행:**
  ```powershell
  cd pipeline
  .venv\Scripts\skpipe analyze ..\samples\cafe-semi\ep01.mp4 --refs ..\samples\cafe-semi\refs --backend yunet-dino -o out\cafe-semi\ep01-yunet-dino.json
  .venv\Scripts\skpipe evaluate out\cafe-semi\ep01-yunet-dino.json --labels ..\samples\cafe-semi\ep01.labels.csv
  ```
  백엔드만 바꿔 `opencv`·`yunet-dino-color`·`anime-dino`도 같은 방식으로 실행.
- **결과:** 컷 분할은 모든 백엔드에서 정확 (클립 경계 그대로 5컷). 처리 시간 약 5초 (CPU, 40초 영상).

  | 백엔드 | 얼굴 있는 컷 | ok 컷 유사도 (min~max) | **ng 컷 유사도** | 가르는 기준 | 기본 기준값에서 |
  | --- | --- | --- | --- | --- | --- |
  | opencv | 5/5 | 0.608 ~ 0.788 | **0.698** | 없음 (ng가 ok 중앙값보다 높음) | 0.45 → ng 놓침 |
  | **yunet-dino** | 5/5 | 0.553 ~ 0.637 | **0.493** | 0.50 ~ 0.55 (F1 1.00) | 0.60 → ng 잡지만 ok 3개도 이슈 |
  | yunet-dino-color | 5/5 | 0.582 ~ 0.688 | **0.573** | 0.575 (차이 0.009) | 0.65 → ok 3개도 이슈 |
  | anime-dino | 0/5 | – | – | – | 레퍼런스 5장 중 3장에서도 얼굴 못 찾음 |

- **해석**
  - **실사 얼굴 모델은 머리색 변화를 못 본다 — 실제 영상에서도 재현.** SFace는 갈색 머리 컷(0.698)을 정상 컷 대부분보다 더 비슷하다고 판단했다. 실험 1·2의 "색에 둔감한 임베딩" 가설과 같은 결과.
  - **DINOv2 단독이 이번에는 깔끔하게 갈랐다.** 실험 2(사진 묶음)에서는 같은/다른 인물 차이가 0.02였는데, 이번엔 ng 0.493 vs ok 최소 0.553으로 0.06 차이. 레퍼런스를 같은 생성 세션에서 만들어 ok 컷이 레퍼런스와 가까웠던 영향일 수 있다.
  - **기본 기준값 0.60은 이 데이터에서 너무 높다** (ok 컷 3개가 이슈). 0.55 근처가 맞아 보이지만 라벨 5개로 바꾸면 과적합 — 실험 2와 같은 이유로 보류.
  - 색 특징을 섞으면 경계가 오히려 좁아졌다 (실험 2와 같은 경향).
  - `anime-dino`는 반실사에서 검출률 0%. 실험 1(33%)보다 나쁘다 → 반실사 시리즈에는 쓰면 안 된다.
- **예상 못 한 오탐: 배경의 작은 얼굴.** minho 컷(0:08~0:16)에서 "yuna 유사도 낮음(opencv 0.339)" 이슈가 나왔는데, 키프레임을 보니 Veo가 배경 테이블에 **yuna를 작게(얼굴 44×54px, 옆모습) 넣어** 둔 것이었다. 사람이 라벨링할 때 놓친 등장이고, 판정은 "누구인지는 맞지만 너무 작아 점수가 낮음". 실제 연재물에서도 배경 인물은 흔하다.
- **다음**
  1. 작은 얼굴 규칙: 화면 대비 얼굴 크기 하한 아래는 이슈에서 빼거나 "확인 필요"로 낮추기
  2. ep02 만들기 (점 누락·다른 얼굴·의상 변경 컷) → 라벨을 늘린 뒤 `yunet-dino` 기준값 다시 정하기
  3. 반실사에서 `anime-dino` 대신 YuNet으로 다시 찾기 (실험 2 다음 3번과 같음)
  4. 컷 하나에 얼굴이 여러 개일 때 라벨이 "어느 얼굴"인지 지정할 방법 (지금은 컷 안 최고 유사도로 평가)
