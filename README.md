# SeriesKeeper

> AI로 만든 연재형 드라마·애니메이션을 **시리즈 단위로 관리**하고, 회차 사이에서 **일관성이 깨진 컷을 자동으로 찾아 주는** 웹 서비스

> 🛠️ **상태: MVP 개발 중.** 웹 화면(시리즈·캐릭터·장소·회차 관리, 검수 리포트)과 분석 워커가 로컬에서 동작합니다. 아직 배포 전이며, 서비스 이름은 가칭입니다.
>
> 🙋 **팀원을 찾고 있습니다.** [함께하기](#함께하기)를 봐 주세요.

---

## 왜 만드나

AI 영상 생성 도구로 한 편은 쉽게 만들 수 있지만, 수십 화짜리 연재물에서는 캐릭터 얼굴·의상, 장소 배치, 인물 시선이 회차마다 달라집니다. 생성 도구들은 "잘 만들기"에 집중하고, **만든 뒤 시리즈 전체를 검수하는 도구는 드뭅니다.**

해결하려는 문제:

- 회차·컷이 늘어날수록 사람이 일일이 보며 일관성을 확인하기 어렵다.
- 캐릭터·장소 설정이 프롬프트와 파일에 흩어져 있어 다음 회차에 다시 쓰기 어렵다.
- 여러 언어로 배포할 때 인물 이름·호칭 번역이 회차마다 달라진다.

## 누구를 위한 서비스인가

언어·국가와 상관없이, AI로 **같은 캐릭터가 나오는 영상을 여러 편 이상 연재하는 사람**.

| 사용자 | 예시 | 가장 큰 불편 |
| --- | --- | --- |
| 1인 AI 드라마·만극 채널 | 유튜브·틱톡 연재 채널 | 혼자 수백 컷을 눈으로 검수 |
| 소규모 제작 스튜디오 | 채널 여러 개를 동시 운영 | 작업자마다 설정을 다르게 쓰는 문제 |
| 교육·브랜드 시리즈 제작자 | 캐릭터가 나오는 설명 영상 | 브랜드 캐릭터가 편마다 달라짐 |

### 대표 사용 흐름

1. 시리즈를 만들고 주인공·조연 레퍼런스 이미지, 주요 장소 이미지를 등록한다.
2. 새로 만든 12화 영상을 업로드한다.
3. 서비스가 컷을 나누고, 각 컷의 인물을 **시리즈 바이블**과 비교한다.
4. `03:12 컷에서 주인공 얼굴 유사도 낮음` 같은 리포트를 받고, 이슈마다 해결·오탐을 표시한다.
5. 문제 컷만 다시 생성해 업로드한다.

## 기능

MVP는 **"시리즈 바이블 + 컷 단위 일관성 검사"** 두 가지만 끝까지 만들고, 나머지는 MVP가 돌아간 뒤 붙입니다.

| 단계 | 기능 | 설명 | 상태 |
| --- | --- | --- | --- |
| MVP | 시리즈·회차 관리 | 로그인, 시리즈 생성·수정·삭제, 회차별 영상 업로드와 분석 상태 표시 | ✅ |
| MVP | 시리즈 바이블 | 캐릭터(각도별)·장소 레퍼런스 이미지와 설명 저장 | ✅ |
| MVP | 컷 분할 | 장면 전환 감지로 영상을 컷으로 나누고 대표 프레임 추출 | ✅ |
| MVP | 캐릭터 일관성 검사 | 얼굴 임베딩으로 컷별 인물을 바이블과 매칭, 유사도가 낮은 컷 표시 | ✅ |
| MVP | 검수 리포트 | 회차별 이슈 목록(타임코드, 사유, 점수), 레퍼런스와 비교 패널, 해결·오탐 표시 | ✅ |
| MVP | 배포 | 웹·워커 서버 배포 | ⏳ |
| MVP | 외형 묘사 자동 생성 | 비전 LLM이 레퍼런스 이미지에서 표준 묘사 문장을 생성 | ⏳ |
| 확장 1 | 의상·배경 검사 | CLIP 유사도로 의상과 장소 배경 비교 | 계획 |
| 확장 1 | 장소 배치·시선 검사 | 문·가구 위치, 인물이 화면 어느 쪽을 보는지 비교 | 계획 |
| 확장 2 | 프롬프트 내보내기 | 바이블 내용을 생성 도구별 프롬프트로 변환해 다음 회차에 재사용 | 계획 |
| 확장 2 | 다국어 용어집 | 인물 이름·호칭·말투를 언어별로 고정해 자막 번역에 적용 | 계획 |

## 아키텍처

웹과 영상 분석을 분리해, 수 분씩 걸리는 분석이 화면을 멈추지 않게 합니다. 처음 계획한 FastAPI + Redis 큐 대신, **Supabase가 DB·인증·스토리지·작업 큐 역할을 함께 맡도록** 단순화했습니다.

```
 [Next.js 웹 (서버 액션)]
         │  회차 업로드 → episode.status = pending
         ▼
 [Supabase]  PostgreSQL (RLS) · Auth · Storage (영상·레퍼런스·이슈 프레임)
         ▲
         │  pending 회차를 하나씩 가져감 (FOR UPDATE SKIP LOCKED)
         │  분석 후 shot·issue 저장, status = done / failed
 [분석 워커 (Python, skpipe worker)]
   컷 분할 → 대표 프레임 → 얼굴 검출·임베딩 → 바이블과 유사도 비교
```

- 큐는 `episode.status`로 충분합니다. 워커를 여러 개 띄워도 같은 회차를 중복으로 가져가지 않습니다.
- 자세한 내용은 [pipeline/README.md](pipeline/README.md), [web/README.md](web/README.md), [supabase/README.md](supabase/README.md)에 있습니다.

### 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 웹 | Next.js 16 (App Router), TypeScript, Tailwind 4 | 서버 액션으로 별도 API 서버 없이 시작 |
| DB·인증·스토리지 | Supabase (PostgreSQL + RLS, Auth, Storage) | 한 곳에서 관리, 행 단위 권한 |
| 분석 워커 | Python (`skpipe`) | ML 라이브러리와 같은 언어 |
| 컷 분할 | PySceneDetect, ffmpeg | 검증된 오픈소스 |
| 얼굴 비교 | OpenCV YuNet + SFace | CPU로 충분, 상업적 사용 가능한 라이선스. InsightFace로 교체 가능하게 설계 |
| CI | GitHub Actions | 파이프라인 테스트, 웹 타입·린트 검사 |
| 의상·배경 비교 (예정) | CLIP 또는 DINOv2 | 이미지 유사도 임베딩 |

### 데이터 모델

시리즈 → 회차 → 컷 순서로 내려가고, 캐릭터·장소는 시리즈에 붙습니다. 이슈는 컷과 캐릭터를 잇습니다. 마이그레이션은 [supabase/migrations](supabase/migrations)에 있습니다.

| 테이블 | 내용 |
| --- | --- |
| `series` | 시리즈 (소유자, 제목, 스타일 메모) |
| `character`, `reference_image` | 캐릭터와 각도별 레퍼런스 이미지 |
| `location`, `location_image` | 장소와 레퍼런스 이미지 |
| `episode` | 회차 영상과 분석 상태 (대기·분석 중·완료·실패) |
| `shot` | 컷 (시작·끝 시간, 대표 프레임) |
| `issue` | 일관성 이슈 (유형, 점수, 해결·오탐 표시) |

## 차별점

| 구분 | 예시 | 이 서비스와의 차이 |
| --- | --- | --- |
| 일관성 캐릭터 생성기 | Leonardo, Midjourney, Atlabs | 생성 단계. 만든 뒤 검수는 하지 않음 |
| 올인원 제작 플랫폼 | 360 나미만극 파이프라인, PixTV | 자사 도구 안에서만 동작. 모델 종속 |
| 편집 툴 | CapCut, Premiere | 일관성 판단 기능 없음 |

- **모델 독립적** — 어떤 생성 모델로 만든 영상이든 검사할 수 있어, 모델이 바뀌어도 쓸모가 유지됩니다.
- **시리즈 단위 비교** — 한 클립이 아니라 회차를 넘나들며 비교합니다.
- **배치·시선까지** — 장소 배치와 시선 방향처럼 생성 모델이 아직 약한 영역을 다루는 것을 목표로 합니다.

## 성공 지표

- **얼굴 일관성 검출** — 직접 라벨링한 테스트셋에서 정밀도·재현율 측정
- **처리 시간** — 10분 회차 한 편당 분석 완료까지 걸리는 시간
- **사용자** — 실제 크리에이터 5명 이상 사용, "다음 회차에도 쓰겠다" 응답 비율

> 측정 결과는 배포 후 이 섹션에 채웁니다.

## 알려진 리스크

| 리스크 | 대응 |
| --- | --- |
| 애니·만화체 얼굴에서 실사용 얼굴 인식 모델 정확도가 낮음 | 실사·애니 샘플로 측정. 낮으면 애니 얼굴 검출 모델 또는 CLIP/DINOv2 임베딩으로 교체 |

| 생성 모델이 일관성을 스스로 해결함 | 모델 독립적인 검수·설정 관리에 집중. 장소 배치·시선은 모델이 아직 약한 영역 |
| 사용자 모집이 어려움 | AI 영상 커뮤니티에 무료 사용 제안, 직접 만든 영상으로도 데모 |
| 업로드 영상의 저작권 | 본인이 권리를 가진 영상만 올리도록 약관 명시, 분석 후 원본 삭제 옵션 |

## 시작하기

로컬에서 웹과 워커를 각각 띄웁니다. 둘 다 같은 Supabase 프로젝트를 씁니다.

1. **Supabase** — 프로젝트를 만들고 [supabase/migrations](supabase/migrations)의 SQL을 순서대로 실행 ([supabase/README.md](supabase/README.md))
2. **웹** — `web/.env.local`에 URL과 Publishable key를 넣고 실행 ([web/README.md](web/README.md))
   ```powershell
   cd web
   npm install
   npm run dev
   ```
3. **분석 워커** — `pipeline/.env`에 URL과 Secret key를 넣고 실행 ([pipeline/README.md](pipeline/README.md))
   ```powershell
   cd pipeline
   python -m venv .venv
   .venv\Scripts\python -m pip install -e ".[dev,worker]"
   .venv\Scripts\skpipe models
   .venv\Scripts\skpipe worker
   ```
