# SeriesKeeper

> AI로 만든 연재형 드라마·애니메이션을 **시리즈 단위로 관리**하고, 회차 사이에서 **일관성이 깨진 컷을 자동으로 찾아 주는** 웹 서비스

> 🚧 **상태: 기획 단계** — 아직 코드가 없습니다. 아래 내용은 계획이며, 개발이 진행되면서 바뀔 수 있습니다. (서비스 이름도 가칭입니다)

---

## 왜 만드나

AI 영상 생성 도구로 한 편은 쉽게 만들 수 있지만, 수십 화짜리 연재물에서는 캐릭터 얼굴·의상, 장소 배치, 인물 시선이 회차마다 달라집니다. 생성 도구들은 "잘 만들기"에 집중하고, **만든 뒤 시리즈 전체를 검수하는 도구는 드뭅니다.**

해결하려는 문제:

- 회차·컷이 늘어날수록 사람이 일일이 보며 일관성을 확인하기 어렵다.
- 캐릭터·장소 설정이 프롬프트와 파일에 흩어져 있어 다음 회차에 다시 쓰기 어렵다.
- 여러 언어로 배포할 때 인물 이름·호칭 번역이 회차마다 달라진다.

## 누구를 위한 서비스인가

언어·국가와 상관없이, AI로 **같은 캐릭터가 나오는 영상을 여러 편 이상 연재하는 사람**.

| 사용자 | 예시 | 가장 큰 불편 |
| --- | --- | --- |
| 1인 AI 드라마·만극 채널 | 유튜브·틱톡 연재 채널 | 혼자 수백 컷을 눈으로 검수 |
| 소규모 제작 스튜디오 | 채널 여러 개를 동시 운영 | 작업자마다 설정을 다르게 쓰는 문제 |
| 교육·브랜드 시리즈 제작자 | 캐릭터가 나오는 설명 영상 | 브랜드 캐릭터가 편마다 달라짐 |

### 대표 사용 흐름

1. 시리즈를 만들고 주인공·조연 레퍼런스 이미지, 주요 장소 이미지를 등록한다.
2. 새로 만든 12화 영상을 업로드한다.
3. 서비스가 컷을 나누고, 각 컷의 인물·장소를 **시리즈 바이블**과 비교한다.
4. `03:12 컷에서 주인공 얼굴 유사도 낮음`, `거실 문 위치가 이전 회차와 다름` 같은 리포트를 받는다.
5. 문제 컷만 다시 생성해 업로드한다.

## 기능

MVP는 **"시리즈 바이블 + 컷 단위 일관성 검사"** 두 가지만 끝까지 만들고, 나머지는 MVP가 돌아간 뒤 붙입니다.

| 단계 | 기능 | 설명 |
| --- | --- | --- |
| MVP | 시리즈·회차 관리 | 시리즈 생성, 회차별 영상 업로드, 로그인 |
| MVP | 시리즈 바이블 | 캐릭터·장소별 레퍼런스 이미지와 외형 설명 저장. 비전 LLM이 이미지에서 표준 묘사 문장을 자동 생성 |
| MVP | 컷 분할 | 장면 전환 감지로 영상을 컷으로 나누고 대표 프레임 추출 |
| MVP | 캐릭터 일관성 검사 | 얼굴 임베딩으로 컷별 인물을 바이블과 매칭, 유사도가 낮은 컷 표시 |
| MVP | 검수 리포트 | 회차별 문제 컷 목록(타임코드, 사유, 점수)과 썸네일 비교 화면 |
| 확장 1 | 의상·배경 검사 | CLIP 유사도로 의상과 장소 배경 비교 |
| 확장 1 | 장소 배치·시선 검사 | 문·가구 위치, 인물이 화면 어느 쪽을 보는지 비교 |
| 확장 2 | 프롬프트 내보내기 | 바이블 내용을 생성 도구별 프롬프트로 변환해 다음 회차에 재사용 |
| 확장 2 | 다국어 용어집 | 인물 이름·호칭·말투를 언어별로 고정해 자막 번역에 적용 |

## 아키텍처

웹 서비스와 영상 분석을 분리해, 수 분씩 걸리는 분석이 화면을 멈추지 않게 합니다.

```
 [Next.js 프론트엔드]
         │  회차 업로드
         ▼
 [FastAPI 백엔드] ──── 분석 작업 등록 ───▶ [Redis 큐]
         │                                    │
         │                                    ▼
         │                           [분석 워커 (Celery/RQ)]
         │                            컷 분할 → 임베딩 → 바이블 비교
         │                                    │
         ▼                                    ▼
 [PostgreSQL + pgvector]  ◀──── 결과 저장 ────┘
 [스토리지 (R2 / Supabase Storage)]  ← 영상·프레임 파일
```

### 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프론트엔드 | Next.js, TypeScript, Tailwind | 배포가 쉽고 채용 수요가 많음 |
| 백엔드 | FastAPI (Python) | ML 코드와 같은 언어 |
| 작업 큐 | Redis + Celery (또는 RQ) | 영상 분석은 비동기 처리 필수 |
| DB | PostgreSQL + pgvector (Supabase) | 관계형 데이터와 벡터 검색을 한 곳에서, 인증 포함 |
| 스토리지 | Cloudflare R2 또는 Supabase Storage | 영상·프레임 파일 저장 |
| 컷 분할 | PySceneDetect, ffmpeg | 검증된 오픈소스 |
| 얼굴 비교 | InsightFace (ArcFace) | 실사 얼굴 임베딩의 표준. 애니체는 별도 검증 필요 |
| 의상·배경 비교 | CLIP 또는 DINOv2 | 이미지 유사도 임베딩 |
| 외형 묘사 생성 | 비전 LLM API | 레퍼런스 이미지에서 표준 설명 문장 생성 |

### 데이터 모델

시리즈 → 회차 → 컷 순서로 내려가고, 캐릭터·장소는 시리즈에 붙습니다. 검사 결과는 컷과 바이블 항목을 잇습니다. 임베딩은 pgvector에 저장해 별도 벡터 DB 없이 유사도 검색을 합니다.

| 테이블 | 주요 컬럼 |
| --- | --- |
| `series` | id, owner_id, title, style_note, created_at |
| `character` | id, series_id, name, description, face_embedding (vector) |
| `location` | id, series_id, name, description, layout_note |
| `reference_image` | id, character_id 또는 location_id, image_url, embedding (vector) |
| `episode` | id, series_id, number, video_url, status (대기·분석중·완료) |
| `shot` | id, episode_id, start_ms, end_ms, keyframe_url |
| `detection` | id, shot_id, character_id, bbox, similarity |
| `issue` | id, shot_id, type (얼굴·의상·배경·배치), score, resolved |

## 로드맵 (8주)

앞 4주에 MVP를 배포하고, 뒤 4주는 사용자 피드백과 확장 기능에 씁니다. 시작 날짜는 미정입니다.

- [ ] **1주차** — 크리에이터 커뮤니티에서 불편 조사, 샘플 영상 3~5개 확보, 화면 와이어프레임
- [ ] **2주차** — 컷 분할 + 얼굴 임베딩 파이프라인을 노트북에서 검증 (임계값 잡기)
- [ ] **3주차** — 백엔드 API, DB, 비동기 분석 작업 큐 구현
- [ ] **4주차** — 프론트엔드(바이블, 업로드, 리포트 화면) + 배포. **MVP 공개**
- [ ] **5주차** — 크리에이터 5~10명에게 사용 요청, 피드백 수집
- [ ] **6주차** — 피드백 반영, 의상·배경 검사 (확장 1)
- [ ] **7주차** — 프롬프트 내보내기 또는 장소 배치 검사 중 하나 선택해 구현
- [ ] **8주차** — 성능 측정(정확도·처리 시간), README·데모 영상·회고 작성

## 차별점

| 구분 | 예시 | 이 서비스와의 차이 |
| --- | --- | --- |
| 일관성 캐릭터 생성기 | Leonardo, Midjourney, Atlabs | 생성 단계. 만든 뒤 검수는 하지 않음 |
| 올인원 제작 플랫폼 | 360 나미만극 파이프라인, PixTV | 자사 도구 안에서만 동작. 모델 종속 |
| 편집 툴 | CapCut, Premiere | 일관성 판단 기능 없음 |

- **모델 독립적** — 어떤 생성 모델로 만든 영상이든 검사할 수 있어, 모델이 바뀌어도 쓸모가 유지됩니다.
- **시리즈 단위 비교** — 한 클립이 아니라 회차를 넘나들며 비교합니다.
- **배치·시선까지** — 장소 배치와 시선 방향처럼 생성 모델이 아직 약한 영역을 다루는 것을 목표로 합니다.

## 성공 지표

- **얼굴 일관성 검출** — 직접 라벨링한 테스트셋에서 정밀도·재현율 측정 (목표치는 2주차 측정 후 설정)
- **처리 시간** — 10분 회차 한 편당 분석 완료까지 걸리는 시간
- **사용자** — 실제 크리에이터 5명 이상 사용, "다음 회차에도 쓰겠다" 응답 비율

> 측정 결과는 개발이 진행되면 이 섹션에 채웁니다.

## 알려진 리스크

| 리스크 | 대응 |
| --- | --- |
| 애니·만화체 얼굴에서 실사용 얼굴 인식 모델 정확도가 낮음 | 2주차에 실사·애니 샘플로 먼저 측정. 낮으면 애니 얼굴 검출 모델 또는 CLIP/DINOv2 임베딩으로 교체 |
| 긴 영상 분석에 GPU 비용·시간이 큼 | 컷당 대표 프레임 몇 장만 분석, 무료 GPU(Colab 등) 또는 서버리스 GPU 사용 |
| 생성 모델이 일관성을 스스로 해결함 | 모델 독립적인 검수·설정 관리에 집중. 장소 배치·시선은 모델이 아직 약한 영역 |
| 사용자 모집이 어려움 | Reddit·디스코드 AI 영상 커뮤니티에 무료 사용 제안, 직접 만든 영상으로도 데모 |
| 업로드 영상의 저작권 | 본인이 권리를 가진 영상만 올리도록 약관 명시, 분석 후 원본 삭제 옵션 |

## 시작하기

아직 실행할 코드가 없습니다. 3~4주차에 백엔드·프론트엔드가 구현되면 로컬 실행 방법을 여기에 추가합니다.
